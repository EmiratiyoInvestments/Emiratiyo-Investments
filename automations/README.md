# Emiratiyo Blog Automation

An n8n workflow that generates a Dubai real estate blog post using Gemini, attaches a relevant cover photo from Unsplash, and creates it as a draft document in Sanity.



## Pipeline

| Step | Node | What it does |
|---|---|---|
| 1 | Generate Blog Content | Calls Gemini, returns title, excerpt, tags, body as JSON |
| 2 | Parse Blog JSON | Cleans and parses the response, builds an Unsplash search query from the first tag |
| 3 | Search Unsplash Photo | Finds one landscape photo matching the query |
| 4 | Create Sanity Draft | Creates the blog document as a draft, including the cover image URL and photo credit |

## Requirements

| Service | What you need | Where to get it |
|---|---|---|
| Gemini API | An API key | [Google AI Studio](https://aistudio.google.com/apikey) |
| Unsplash API | An Access Key | [unsplash.com/oauth/applications](https://unsplash.com/oauth/applications) |
| Sanity | A write token for the project | Sanity manage console, under API > Tokens |

The Sanity project ID (`kgljxpj0`) and dataset (`production`) are already set in the workflow's URLs.

## Setup

1. Import `emiratiyo-blog-automation.blueprint.json` into n8n.
2. On the **Generate Blog Content** node, replace the placeholder in the URL's `key=` parameter with your real Gemini key.
3. Create two n8n credentials of type **Header Auth**:

```
Unsplash Header Auth
  Name:  Authorization
  Value: Client-ID <your Unsplash access key>

Sanity Header Auth
  Name:  Authorization
  Value: Bearer <your Sanity token>
```

4. Attach **Unsplash Header Auth** to the **Search Unsplash Photo** node, and **Sanity Header Auth** to the **Create Sanity Draft** node, both via `Authentication > Generic Credential Type > Header Auth`.
5. Run once from **Manual Trigger** to confirm all three services respond correctly.

## Schedule

The workflow imports as **Inactive**, so nothing runs on its own yet. The **Every 2 Days** node is already configured with a two day interval.

To go live, toggle the workflow to **Active** in n8n. From that moment it will run automatically every two days. Until then, use **Manual Trigger** whenever you want to generate a post.

## Related changes outside this workflow

These live in the main site repo, not here, but are required for the cover image to actually display:

* **Sanity schema** (`blog` document type): two added fields, `coverImageUrl` (type `url`) and `coverImageCredit` (type `string`), both optional.
* **GROQ query** (`src/lib/sanity/blogQueries.js`): `SINGLE_BLOG_QUERY` requests both new fields.
* **Blog post page** (`src/pages/BlogsDetailsPage.jsx`): renders `coverImageUrl` if present, falls back to the older `mainImage` field otherwise, and shows the photo credit text underneath.

## Notes

* The Unsplash header value must include the `Client-ID ` prefix before the key itself, not just the raw key.
* The Sanity header value must include the `Bearer ` prefix before the token.
* Only the Unsplash **Access Key** is used. The Secret Key is for a different auth flow and isn't needed here.
* Cover images are sourced from Unsplash's free stock library based on the post's first tag, not generated by AI. This was a deliberate cost and quality tradeoff, not a limitation to fix later.
* If this file ever gets pushed to a shared or public repository, double check that no real API keys are pasted into the workflow JSON before committing.
